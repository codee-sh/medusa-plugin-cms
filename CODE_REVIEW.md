# Code review

Review rules for this repository. They apply whether the reviewer is a human or a skill, and they sit on
top of, never instead of, the conventions skills named in the Skill Router in [AGENTS.md](AGENTS.md).

The stack under review: a Medusa v2 plugin in TypeScript, built with `medusa plugin:build`, with Admin
extensions in React, tested with Jest.

## Review priorities

Read the diff in this order. A finding high on the list outranks a finding lower down when review time is
short.

1. **Correctness against the spec.** For anything non-trivial there is a spec under `.ai/specs/`. Check the
   change against it, not against a guess at the intent.
2. **Data and contract safety.** The config types, API shapes, workflow inputs and outputs, and exported
   functions are the plugin's public contract. A breaking change must be deliberate and stated.
3. **Genericity.** Nothing names a collection, block or model of a project.
4. **Test coverage at the right altitude.** Per `codee-medusa-testing`: every new step, workflow, API route
   and exported util owes the test named in its altitude table, or an explicit reason why not.
5. **Convention compliance.** TypeScript and Medusa conventions, Admin form structure, UI copy.
6. **Clarity.** Naming that states what a value represents; JSDoc where the conventions require it.

## Repo-specific checks

- **Cache write without `clear({ key })` - blocker.** Also a blocker: a test cache mock that overwrites a
  live key. Background: [clear-a-cache-key-before-rewriting-it](.ai/lessons/clear-a-cache-key-before-rewriting-it.md).
- **A migration file in the diff - blocker.** The one exception is the test module's
  `integration-tests/modules/test-content/migrations/`, generated by the user with `yarn test:db:generate`
  and committed with its `.snapshot-test-content.json`.
- **A cycle of cascades in a test model or a documented example - blocker.** Background:
  [a-cycle-of-cascades-makes-every-soft-delete-throw](.ai/lessons/a-cycle-of-cascades-makes-every-soft-delete-throw.md).
- **A generated `restore` called directly - blocker.** Compensation restores through `restoreRows`.
  Background: [a-cascading-restore-brings-back-rows-deleted-earlier](.ai/lessons/a-cascading-restore-brings-back-rows-deleted-earlier.md).
- **A public store field outside an allowed list - blocker.** A store read returns only what the registry
  and `allowedFields` permit.
- **Workflows and steps.** Per `codee-medusa-backend-conventions`. A step with compensation owes a test of
  both directions.
- **Metadata updates.** Medusa merges `metadata`, so removing a key means sending `""`, and an inverse write
  must do the same.
- **JSDoc discipline** per `codee-ts-code-conventions`.
- **English only** in code, comments, identifiers, and documentation.
- **Scope.** No refactors outside the task.
- **Secrets.** No tokens, `.env` content, or credentials in code, tests, fixtures, comments, or commit
  messages.

## The validation gate in review

A change is not reviewable as complete until the gate in [SDLC.md](SDLC.md) has been run and its result
reported. A reviewer must not accept a claim that integration tests passed unless the report says they were
run manually. Naming a check that was not run, with the reason, is a complete answer. Silence is not.

## Severity

| Severity | Meaning | Effect |
|---|---|---|
| **Blocker** | Data loss, a silent-failure trap from the list above, a contract break, a security defect, or a contradiction of an active spec | Request changes. |
| **Major** | A real defect in the happy path, a missing test the altitude table requires, or a convention breach that will propagate | Request changes, unless the author states why it is deferred. |
| **Minor** | Naming, comment density, small clarity wins | Note it; does not hold the commit. |

When signals conflict, pick the higher severity and say why.

## Reporting a review

State what you actually checked and what you ran. A finding without a concrete failure path is a question,
not a finding.
